# 수업 전 실제 폰 점검표

테스트용 수업에서 진행하세요. 실제 수업의 투자 기록이 있으면 먼저 CSV와 DB 백업을 보관합니다.

준비: 대표 폰 3대(아이폰 Safari, 갤럭시 Chrome 포함), 강사 노트북, 프로젝터. 6개 회사·조당 5,000만 원·타이머 5분을 설정합니다. 날짜/기종/브라우저/학교망을 기록합니다.

| 완료 | 점검 방법 | 정상 결과 |
|---|---|---|
| ☐ | 강사 로그인, 회사 이름 입력 후 엔터, 고급 설정 저장 | 다음 이름 칸으로 이동하고 6개 회사 설정이 저장됨 |
| ☐ | 코드 카드 인쇄, 현황판 열기, QR 크게 보기 | 한 A4에 카드 6개. 현황판에는 입장 코드가 없고 강사에 현황판 연결 표시 |
| ☐ | 폰 3대로 대표 실명과 서로 다른 코드 입력. 한 폰은 붙여넣기 | 4자리 완료 후 자기 회사로 입장. 시작 전 대기. 회사 목록은 입장 전에 보이지 않음 |
| ☐ | 카카오톡에서 링크 열고 주소 복사 후 Safari/Chrome 접속 | 외부 브라우저 안내 표시. 먼저 일반 브라우저로 이동해 입장. 이미 접속했다면 강사가 해제한 뒤 새 브라우저 입장 |
| ☐ | 다른 기기로 같은 코드를 입력 | 두 번째 기기는 입장 거부, 첫 기기의 작성·연결 유지. 강사 해제 후 새 기기만 입장하고 기존 제출 상태 유지 |
| ☐ | 투자 시작. 3대에서 서로 다른 대상에 전액 배분 | 새로고침 없이 시작. 자기 회사가 대상에 없고 남은 금액 정확 |
| ☐ | 빈 이유·미배분·합의 미체크로 제출 시도 | 제출할 수 없음. 빈칸이 아닌 이유·전액·합의 이후 제출 가능 |
| ☐ | 두 폰을 동시에 제출하고 초시계로 현황판 반영 시간 기록 | 중복 없이 둘 다 반영. 정상망에서는 통상 5초 이내, 10초 이상이면 망/API 점검. 실제 측정 ___초 |
| ☐ | 세 번째 폰에 금액·이유 입력 후 와이파이 끄고 LTE로 전환 | 내용 유지되고 서버 연결 복구. 이어 와이파이/LTE 모두 잠시 끈 뒤 복구·새로고침 | 
| ☐ | 위 완전 오프라인 상황에서 작성 내용을 확인 | 연결 중 표시가 버튼을 가리지 않고 복구 후 금액·이유가 그대로 남음 |
| ☐ | 강사 폰 390px 정도 폭에서 진행 탭 확인 | 스크롤 없이 상태·제출 수·투자 마감 버튼 확인. 미제출 회사가 위쪽 |
| ☐ | 타이머 +1분, 강사 마감, 결과 공개 | 남은 시간 증가. 마감 후 입력 잠김. 공개 전에는 대기, 공개 후 낮은 순위부터 발표 |
| ☐ | 투자 재개 후 제출한 회사 더보기 → 제출 취소 | 해당 회사 폰에 기존 금액·이유 복원. 다른 회사에는 내역이 전달되지 않음 |
| ☐ | 복원 내용 수정 후 재제출 | 한 번만 제출되고 총액은 이전 제출과 이중 합산되지 않음 |
| ☐ | 다시 마감하고 더보기 확인, 회고 회사 넘기기 | 제출 취소가 없음. 회사별 받은 이유를 읽을 수 있음 |
| ☐ | 관리 탭에서 CSV 두 종류 저장 후 엑셀 열기 | 한글·금액·보낸 회사·받은 회사·이유가 올바름 |
| ☐ | 전체 초기화 두 번 확인, 설정 유지 끄기 | 6개 회사 유지, N조 회사 이름, 기본 투자금/타이머, 기본 코드(1001·2001…), 투자 0건 |
| ☐ | 초기화 후 다시 시작·입장 | 다음 수업을 정상적으로 진행 가능 |

추가 실패 제한 점검도 테스트 수업에서만 합니다. 다른 기기의 강사 로그인 5회 실패 뒤 강사 폰에서 정상 로그인되는지 확인합니다. 학생 코드 5회 실패 후 60초 대기, 강사의 입장 제한 해제 후 재시도가 가능한지 확인합니다. 코드 재발급 후 이전 코드는 거부돼야 합니다. 전역 50/100회 실패는 자동 테스트로 검증하며 실제 수업에서 고의로 반복하지 마세요.

실제 iPhone SE에서 숫자 키패드·붙여넣기·이유 입력 키보드를 확인합니다. 하단 버튼이 입력칸을 가리거나 가로 스크롤이 생기면 안 됩니다. 프로젝터 뒷자리에서 긴 이름과 금액이 읽히는지, 1위 동률이 올바르게 표시되는지도 확인합니다.

추가 화면 점검: 강사 PC 1600px에서 왼쪽 단계 메뉴·가운데 준비 설정·오른쪽 수업 요약을 함께 확인합니다. 짧은 이유(예: 좋아요)와 60자를 넘는 이유를 각각 제출해 잘리지 않는지, 현황판의 긴 문장을 끝까지 스크롤해 읽을 수 있는지 확인합니다.

조 개수 보정: 테스트 수업을 진행 중으로 만든 뒤 7개→6개로 입력하고 저장합니다. 초기화 확인 전에는 7개와 투자 내역이 유지되고, 확인 후에는 6개·시작 전·투자 0건이어야 합니다. 이어 6개→8개로 늘리면 8개 이름 입력칸과 중복 없는 기본 코드가 표시돼야 합니다. 코드 관리에서 재발급→기본 코드로 복원을 눌러 1조가 다시 1001이 되는지, 투자 내역이 유지되는지 확인합니다.


| 완료 | 새 버전 추가 점검 | 정상 결과 |
|---|---|---|
| ☐ | 실명 없이 올바른 코드 입력 후 입장 시도 | 이름 입력 안내, 회사 연결을 선점하지 않음 |
| ☐ | 강사 진행 탭에서 모둠 대표 확인 | 회사별 대표 이름 표시. 현황판·타 모둠 학생에게는 이름 비노출 |
| ☐ | 같은 모둠 코드로 두 폰에서 거의 동시에 입장 | 먼저 처리된 한 기기만 입장. 두 번째가 첫 기기를 해제하거나 이름을 바꾸지 못함 |
| ☐ | 대표 폰 새로고침, 인터넷 재연결 | 동일 이름·회사·임시 투자 내용 유지 |
| ☐ | 기기 연결 해제 후 교체 폰에서 이름·코드 입력 | 교체 폰 입장, 이전 폰은 더 이상 제출 불가. 기존 제출 내역은 보존 |
| ☐ | 8개 회사 현황판, 10초 경과 | 6개/2개 두 페이지가 자동 전환. 실시간 금액 갱신으로 페이지가 초기화되지 않음 |
| ☐ | 현황판 이전·다음, 일시정지 후 15초 대기 | 수동 이동 즉시 반영, 일시정지 상태에서는 같은 페이지 유지 |
| ☐ | 강사 진행 탭에서 페이지 이동과 자동 넘김 재개 | 현황판이 강사 설정을 따르고 다시 10초 간격 전환 |
| ☐ | 다시 6개 회사로 설정, 모바일 375·390·430px 확인 | 불필요한 넘김 버튼 없음. 가로 스크롤 없음. 핵심 버튼 높이 48px 이상 |

## 7~8명 접속 최종 확인

실제 수업 자료가 없는 사전 연습 수업에서만 진행합니다. 진행 중인 수업을 점검 목적으로 초기화하지 마세요. 아래 항목은 원격 자동 검사로 대신할 수 없는 현장 확인입니다.

| 완료 | 점검 | 정상 결과 |
|---|---|---|
| ☐ | 대표 제한 migration과 해당 프런트엔드 배포 여부 확인 | 학생 입장에 대표 이름 칸이 있고, 다른 폰의 같은 회사 입장은 거부됨 |
| ☐ | 아이폰 Safari·갤럭시 Chrome 포함 7~8대 입장 | 각자 회사명 일치. 8명이 대표라면 회사도 8개 준비. 강사와 현황판까지 동시에 정상 연결 |
| ☐ | 8대에서 동시에 제출하고 시간을 잼 | 각자 제출 완료, 현황판 제출 수 8/8. 합계는 조당 투자금×8, 중복 합산 없음. 반영까지 실제 소요 시간을 기록 |
| ☐ | 학교 와이파이에서 10분간 현황판 유지, 한 폰은 LTE로 전환 | 제출 수·금액 일치, 재접속 후 같은 회사와 작성 내용 유지 |
| ☐ | 실제 아이폰·갤럭시에서 이유 입력 후 키보드 닫기 | 숫자 키패드, 한글 입력·붙여넣기 정상. 내용/제출 버튼 가림, 가로 스크롤 없음 |
| ☐ | 카카오톡 QR로 열고 안내에 따라 Safari/Chrome으로 이동 | 외부 브라우저 안내 표시. **입장 전에** 외부 브라우저로 이동하여 대표 연결이 중복되지 않음 |

여기서 측정한 반영 시간이 수업 진행에 적합한지 확인하세요. 원격 점검의 응답 시간은 학교 와이파이/LTE 성능을 대신하지 않습니다.
