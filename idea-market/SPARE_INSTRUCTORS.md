# 보조 강사 접속 두 개

기존 강사 비밀번호를 유지하고 보조 강사 1·2가 각각 다른 네 자리 비밀번호로 같은 `/admin` 화면에 접속합니다. 로그인 화면의 변경이나 별도 아이디 입력은 필요 없습니다. 세 접속은 같은 수업을 함께 관리하며, 서로 독립된 수업 공간이 아닙니다.

비밀번호 원문은 DB·저장소·학생/현황판 응답에 보관하지 않습니다. private 스키마의 `instructor_credentials`에 bcrypt 해시만 저장합니다. 생성 요청의 응답에만 원문을 한 번 반환합니다. 기존 기기별 로그인 지연·전역 대입 제한은 두 보조 비밀번호에도 동일하게 적용됩니다.

## 적용

`supabase/migrations/20261023124013_spare_instructor_access.sql`을 Supabase migration으로 적용합니다. 해당 migration은 현재 운영 RPC의 로그인 판정과 권한이 필요한 생성 동작만 추가하며, 투자·조 설정·수업 상태·기존 강사 세션을 초기화하지 않습니다. 별도 프런트엔드 배포가 필요하지 않습니다.

현재 강사 세션으로 Edge Function의 `spare_admin` 동작에 `data: {slot: 1}` 또는 `{slot: 2}`를 보내 해당 보조 비밀번호를 발급합니다. 같은 slot에 다시 요청하면 그 보조 비밀번호만 바뀌고, 다른 보조 비밀번호는 유지됩니다. 원문은 안전하게 직접 전달하고 로그/소스/README에 기록하지 않습니다. 관리 화면에 발급 UI는 추가하지 않았습니다.

수업 전체 초기화는 보조 비밀번호를 유지합니다. 관리 화면의 기존 비밀번호 변경은 기본 강사 비밀번호를 변경하며 보조 비밀번호를 재발급하지 않습니다. 이미 로그인한 세션은 기존의 만료·로그아웃 정책을 따릅니다.

대표 이름/한 기기 제한 migration은 별도 작업입니다. 그 migration이 아직 적용되지 않은 운영 서버에도 보조 로그인만 적용할 수 있습니다. 나중에 대표 제한 migration을 적용할 때에는 `install_spare_instructor_login()`을 재호출하는 최신 파일을 사용해 보조 로그인 확장을 유지합니다.

## 검증

`npm test`는 분리 스키마 + 롤백 트랜잭션에서 두 비밀번호의 중복 방지·정상 로그인·기존 비밀번호 유지·재발급 격리·학생/현황판 생성 거부·원문 비노출을 검사합니다. 운영의 실제 확인은 요청한 두 비밀번호 발급과 로그인/관리 화면 읽기로만 진행하며 투자·초기화 테스트는 실행하지 않습니다.
