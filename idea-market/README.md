# 투자 시뮬레이터

고등학생 창업 캠프용 투자 시뮬레이션입니다. Vite, Supabase Edge Function/Postgres/Realtime, Vercel을 사용하며 한 인스턴스에서 한 수업을 운영합니다.

## 화면과 수업 당일 운영 순서

1. `/admin`에서 강사 비밀번호로 로그인합니다. 준비 탭의 1단계에서 − / + 버튼 또는 숫자 입력으로 조 개수(이번 캠프 6개)를 정하고 회사 이름을 저장합니다. 투자금(기본 5,000만 원)과 타이머는 고급 설정에서 조정합니다. 이름 입력 중 엔터는 다음 칸으로 이동합니다.
2. 2단계에서 회사별 입장 코드 카드를 인쇄해 대표에게만 전달합니다. 상단 투자 현황판 열기로 프로젝터에서 전용 주소를 열고 QR 크게 보기를 누릅니다. 고정줄의 현황판 연결 표시를 확인합니다.
3. 대표만 QR로 `/s`에 접속해 대표 실명과 회사 코드 네 자리를 입력합니다. 모둠당 한 기기만 입장하며, 이미 접속한 모둠은 다른 기기에서 입장할 수 없습니다. 같은 기기·브라우저는 새로고침 후 이어서 진행합니다. 카카오톡·네이버에서는 안내에 따라 Safari 또는 Chrome으로 주소를 엽니다.
4. 강사가 투자 시작을 누릅니다. 학생과 현황판이 자동 전환됩니다. 진행 탭은 미제출 회사를 먼저 표시합니다. 타이머를 사용하면 고정줄에서 1분씩 늘릴 수 있습니다.
5. 실수는 회사 줄의 더보기에서 처리합니다. 제출 취소는 마감 전에만 가능하며 기존 금액·이유가 해당 회사 화면에 복원됩니다. 마감 후 수정이 필요하면 먼저 투자를 재개합니다. 연결 해제와 코드 재발급도 사용할 수 있습니다.
6. 마감 후 현황판은 공개 대기 화면을 표시합니다. 강사가 회고 탭의 결과 공개를 눌러야 순위 발표 연출이 실행됩니다. 이후 최종 결과/투자 이유 및 이전/다음 회사로 회고를 진행합니다.
7. 관리 탭에서 유치 총액과 투자 상세 CSV를 모두 저장합니다. 전체 초기화는 두 번 확인합니다. 설정 유지 여부와 관계없이 현재 조 개수는 유지됩니다. 유지하지 않으면 이름을 N조 회사로 바꾸고 투자금·타이머를 기본값으로 되돌립니다. 입장 코드는 기본값(1조 1001·2조 2001·3조 3001…)으로 복원됩니다.

학생에게는 `/s`만 공유합니다. `/board#<전용 키>`는 강사 화면에서 여는 투자 데이터는 보기 전용이고 페이지 넘김만 조작할 수 있는 주소이며 키는 로컬 저장 후 주소에서 제거됩니다. 코드·강사 토큰을 공개하지 마세요. 기기는 브라우저의 무작위 토큰으로 구분하므로 브라우저 변경·시크릿 모드·저장소 삭제는 새 기기로 처리됩니다.

## 로그인 및 입장 지연

강사 로그인 실패는 기기 토큰별로 집계하고 2·4·8·16·30초로 지연합니다. 다른 기기의 실패로 해당 강사 기기를 15분 잠그지 않습니다. 전체 실패가 최근 15분간 50회를 넘으면 각 기기에 최소 30초 간격을 적용합니다. 너무 이른 재시도로 대기 종료 시각이 계속 밀리지 않습니다. 이미 로그인된 세션은 영향을 받지 않습니다.

회사 코드는 기기별 5회 실패 시 60초 대기합니다. 전체 실패가 15분간 100회를 넘으면 각 기기의 시도 간격을 5초로 제한하고 정상 코드는 자신의 대기가 끝나면 입장할 수 있습니다. 공용 대기 시각을 다른 기기가 계속 연장하는 구조가 아닙니다. 강사 고정줄의 입장 제한 해제로 전역·기기별 회사 코드 실패 기록을 지울 수 있습니다.

Supabase 공식 [Turnstile 예제](https://supabase.com/docs/guides/functions/examples/cloudflare-turnstile)는 X-Forwarded-For 사용 예시를 제공하지만 호스팅 환경에서 첫 값의 위조 방지 보장까지 확인하지 못했습니다. 따라서 IP 헤더를 잠금·지연 식별자로 사용하지 않습니다. RPC의 p_ip 인수는 이전 호출과의 호환성만 위해 남았습니다.

비상시 관리자가 실행할 로그인 실패 초기화 SQL 한 줄입니다. 수업·투자·로그인된 세션은 삭제하지 않습니다.

```sql
TRUNCATE idea_private.login_attempts, idea_private.login_failures, idea_private.attempts;
```

## 데이터 보호와 연결

서버에서 자기 회사 투자 금지, 100만 원 단위, 전액 배분, 빈칸이 아닌 투자 이유, 조원 합의, 중복 제출을 검사합니다. 학생 응답은 해당 기기가 소유한 회사의 제출/복원 내역만 포함합니다. 다른 회사의 결과와 모든 입장 코드는 제외합니다. 코드는 비공개 idea_private 스키마에 평문 저장하고 강사에게만 반환합니다. 공개 Realtime 테이블에는 변경 신호만 기록합니다.

Realtime과 별도로 진행 중 3초, 나머지 상태 10초 간격으로 스냅샷을 가져옵니다. WebSocket이 차단돼도 API가 연결되면 계속 갱신합니다. API까지 끊기면 학생 화면에 연결 중 표시가 나타나고 기기 임시 저장을 유지합니다. 서버 마감 이후 제출은 거절됩니다. 현황판 연결 표시는 최근 45초 이내 조회 여부이며 프로젝터 전원이나 화면 가시성을 보장하지는 않습니다.

실제 검증 범위는 [VERIFICATION.md](VERIFICATION.md), 실물 폰 수업 전 점검은 [FIELD_TEST.md](FIELD_TEST.md)를 확인하세요.

## 기존 운영 DB 적용 방법

2026-10-23 사용자 배포 지시에 따라 아래 migration 네 개와 Edge Function v2를 운영에 적용하고, main 병합 후 Vercel 배포를 완료했습니다. 기존 7개 회사·투자 내역 5건·진행 중 상태를 유지했습니다. 이후 설치·업데이트 때도 다음 순서를 지켜 DB와 프런트엔드 버전이 어긋나지 않게 적용합니다.

1. 수업 종료 후 CSV와 DB 백업을 확보합니다. 별도 Supabase 테스트 프로젝트에 현재 운영 스키마를 복제하고 아래 migration을 먼저 적용합니다.
2. 기존 migration 이력을 확인하고 `supabase/migrations/`의 다음 네 파일을 순서대로 검토·적용합니다. 각 파일은 트랜잭션 안에서 실행하고 실패 시 롤백합니다. 운영에는 검토된 migration만 적용합니다.
   - `20261022155414_classroom_access_delays.sql`
   - `20261022155416_classroom_submission_recovery.sql`
   - `20261022155419_classroom_presentation_controls.sql`
   - `20261023000100_unrestricted_investment_reasons.sql`
3. `supabase/schema.sql`은 새 설치의 기준 스키마입니다. 기존 운영 DB에 전체 재실행하지 마세요. 과거 company_codes.sql/reopen_investment.sql도 이번 migration 뒤에 재실행하지 마세요. 함수 정의를 과거 버전으로 되돌릴 수 있습니다.
4. Edge Function은 `supabase/edge.ts`와 `supabase/edge-handler.js`를 함께 배포합니다. 기존 배포 방식의 엔트리포인트를 유지하거나 아래처럼 기본 디렉터리에 두 파일을 복사해 CLI로 배포합니다. service_role 키는 서버 환경에만 둡니다.

```sh
mkdir -p supabase/functions/idea-market
cp supabase/edge.ts supabase/functions/idea-market/index.ts
cp supabase/edge-handler.js supabase/functions/idea-market/edge-handler.js
supabase functions deploy idea-market --project-ref YOUR_PROJECT_REF --no-verify-jwt
```

5. 테스트 프로젝트에서 FIELD_TEST를 완료한 다음 같은 migration과 Edge 변경을 운영에 적용합니다. 그 다음 기능 브랜치를 main에 병합해 Vercel 프런트엔드를 배포합니다. DB 변경 전 새 프런트엔드만 먼저 배포하지 마세요.
6. Vercel Root Directory는 `idea-market`, 빌드는 `npm run build`, 출력은 `dist`입니다. 배포 후 강사·학생·현황판을 새로 열어 적용 버전을 확인합니다.

플랫폼 JWT 검사는 사용하지 않지만 Edge/RPC가 자체 기기·강사·현황판 토큰과 서버 권한을 검사합니다. 되돌릴 때는 운영 데이터를 보존한 채 프런트엔드와 Edge를 이전 버전으로 복구하고, 추가 컬럼/테이블을 급하게 삭제하지 마세요.

## 화면 구성과 투자 이유

PC 강사 화면은 왼쪽 수업 단계, 가운데 설정/진행 작업, 오른쪽 수업 요약으로 구성합니다. 모바일에서는 같은 순서를 세로로 배치합니다. 학생 화면은 금액·빠른 배분·이유 입력을 같은 카드 규격으로 제공하고, 현황판은 순위와 의견을 분리합니다. 한글 Noto Sans KR 가변 글꼴을 앱에 포함하며 글꼴 CDN에 의존하지 않습니다.

투자 이유의 최소/최대 글자 수 제한과 자동 잘라내기를 제거했습니다. 이유 작성 자체는 필수이며 공백만 있는 이유는 서버에서 거절합니다. 긴 이유는 DB와 자기 제출 요약에 그대로 보관하고 현황판에서 줄바꿈·스크롤로 표시합니다. 개별 이유의 글자 수 제한은 없지만 기존 Edge의 전체 요청 크기 보호(16,000자)는 유지됩니다. 글이 매우 길거나 투자 대상이 많으면 전체 요청 크기 제한에 걸릴 수 있습니다.

## 배포 전 화면 미리보기

`npm run build:review`는 운영 화면 코드를 사용하되, 설정과 SDK를 미리보기 전용 모듈로 교체해 dist-review를 만듭니다. 실제 Supabase URL/키/네트워크를 사용하지 않고 브라우저에만 미리보기 데이터를 저장합니다. 운영 빌드에는 포함되지 않습니다.

미리보기는 강사용에 바로 입장하며 로그아웃 후 시험용 비밀번호는 1234입니다. 학생 시험용 코드는 1001·2001·3001·4001·5001·6001이며 대표 이름도 입력합니다.  미리보기 전체 초기화 후에는 강사 화면에 표시한 코드를 사용합니다. 상단의 진행 화면 보기·결과 화면 보기는 시험 데이터를 채우는 전용 도구입니다. 같은 브라우저의 탭끼리만 공유되므로 실제 다기기 동기화 검증을 대신하지 않습니다.

## 조 개수 변경과 기본 코드 복원

조 개수는 준비 탭에서 언제든 2~30개로 입력할 수 있습니다. 진행 중이거나 접속한 학생이 있는 수업에서 조 개수를 바꾸어 저장하면 투자/접속 초기화 확인 화면을 표시합니다. 확인한 경우에만 조 구성 변경과 새 수업 준비를 한 트랜잭션에서 처리합니다. 확인하지 않으면 기존 데이터가 유지됩니다.

회사별 코드 관리를 열면 기본 코드로 복원 또는 새 코드 발급을 선택합니다. 기본 코드는 1~9조는 1001·2001·…·9001, 10~30조는 9002~9022입니다. 무작위 재발급은 이 기본 코드를 사용하지 않아 중복을 예방합니다. 전체 초기화는 설정 유지 여부와 관계없이 기본 코드로 돌아옵니다. 기본 코드 복원은 투자 내역을 유지하고 해당 기기 연결만 해제합니다.

추가 migration은 20261023012000_configurable_team_count.sql 다음 20261023012500_stable_default_company_codes.sql 순서입니다.


## 대표 한 기기 제한·새 디자인·현황판 조작 (검토 버전)

- 학생은 실명(1~30자)과 회사 코드로 입장합니다. 접속한 회사의 다른 기기 입장은 서버에서 TEAM_IN_USE로 거부하며, 기존 대표의 작성 내용·이름·연결을 변경하지 않습니다. 같은 기기 재입장 시 draft_version을 유지합니다. 한 기기로 여러 회사를 잡을 수 없습니다.
- 대표 실명은 강사 응답과 해당 대표 본인 응답에만 포함됩니다. 현황판과 다른 학생에게 전달하지 않습니다. 강사는 진행 탭에서 이름을 확인하고, 잘못된 접속은 더보기→기기 연결 해제로 처리합니다. 폰 교체도 같은 절차이며 이미 제출한 투자 내역은 유지합니다. 코드 재발급·기본 코드 복원·전체 초기화 시 기존 대표 이름을 지웁니다.
- 이름 입력은 실명 인증이 아닙니다. 알려진 코드를 먼저 입력한 학생이 조장인지는 강사가 확인해야 합니다. 회사 코드 카드는 대표에게만 전달하세요. 추가 강사 승인 대기 단계는 없습니다.
- 현황판은 6개 회사씩, 회고는 받은 의견 3개씩 표시합니다. 기본 자동 넘김은 10초입니다. 이전/다음 버튼은 자동 넘김 시점을 다시 10초 뒤로 잡고, 일시정지는 재개할 때까지 유지됩니다. 한 페이지면 넘김 버튼을 숨깁니다.
- 강사 진행·회고 탭에서 페이지와 자동 넘김을 원격 조작할 수 있습니다. 서버에 저장된 조작 버전이 현황판에 반영됩니다. 현황판에서 직접 누른 버튼은 그 현황판의 일시 조작이며, 강사가 다시 조작하면 강사 설정을 따릅니다. 현황판 토큰으로 서버 설정이나 투자 데이터를 바꾸는 권한은 부여하지 않았습니다.
- 프리텐다드 1.3.9를 번들에 포함해 외부 폰트 CDN 없이 표시합니다. 폰트 라이선스는 public/fonts/OFL-Pretendard.txt에 포함했습니다.
